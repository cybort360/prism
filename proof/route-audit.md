## Lifecycle closure summary

| Lifecycle | Status |
|---|---|
| Home (greeting, USDC balance readback, Send/Request/Scan/Add money, recent people, incoming request, money-waiting claim, recent activity) | Closed — real data, `balance()` is USDC on-chain readback |
| People (Contacts/Prism tabs, search, on-demand resolution, on/not-on-Prism, identity-change block for phone AND handle) | Closed — `IdentityTrustStore` + `IdentityChangeReviewView` |
| Send (person→amount→note→review→PIN/FaceID→Mera sign→relay→Sending→Settling→Sent) | Closed — never shows Sent before reconciled receipt |
| Unregistered recipient (send anyway → claim funding → waiting/expiry → refund) | Closed — no phone on-chain (random claimId/ref) |
| Claim recipient (money waiting → claim → received; already-claimed/expired/refunded handled) | Closed — dual-signature (eligibility + Mera intent) |
| Request money (OPEN/PAID/DECLINED/CANCELLED/EXPIRED; pay via normal flow; requestId in PaymentSettled) | Closed |
| Activity (bank-statement, filters, search, reconciled/indexed + signed requests, tx detail with collapsed network details) | Closed |
| Profile (identity, reachability, security, privacy, advanced secondary) | Closed |
| QR / links (opaque prismId/handle, never raw wallet) | Closed |
| Add money (USDC address, copy, QR, dev testnet faucet hook, "Add USDC" explanation; no fake fiat) | Closed |
| Recovery (Mera passkey primary; OTP can never seize a funded account; SIM-swap = no financial control) | Closed — enforced in `identityService` + Profile Recovery |

No placeholder buttons, no fake success, no TODO navigation, no hardcoded demo names in production paths.
